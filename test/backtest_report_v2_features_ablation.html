検証⑬ KR指数+伸びギャップのv2特徴量アブレーション

実施: 2026-07-29 / スクリプト: test/verify_v2_features_ablation.py / walk-forward 5fold(2025-12-01〜2026-07-28、backtest.pyと同一の分割・パラメータ) / 評価は実運用と同じ買い方(predictors.ken_portfolio の plan 実額)。 src/ は無改変(v1凍結ルール準拠・新規ファイルのみ)。

判定: 4アームすべて事前登録基準に不合格。v2への特徴量注入は見送り。 主要指標(5場・ken現行構成の全fold合計回収率)は base 96.9% に対し +KR 97.5%(+0.6pt)/ +GAP 97.6%(+0.7pt)/ +BOTH 96.0%(−0.9pt)。 合格ライン「+5.0pt以上 かつ 5fold中4fold以上でbase超え」に対し、 改善幅は1pt未満・base超えfoldも最大3/5で、両条件とも満たさない。 なお KR指数は予測精度そのものは確かに上げている(AUC 0.8424→0.8465、 モデル1位の1着的中 56.9%→57.2%、gain寄与11.8%)—— 「的中率は上がるが回収率は動かない」という本プロジェクトの既知法則の再確認となった。

事前登録(実行前に固定)

  • 動機: 研究期(7/24-29)で単因子として効くと実測された2つを、手動コンボ(3連敗で打ち止め)ではなく モデルの特徴量として与え、掛け算はLightGBMに探させる
  • アームは4つに固定し、実行後に増やさない: A base(現行31特徴量)/ B +KR(+kr_rating, kr_rel)/ C +GAP(+rising_gap)/ D +BOTH(4列すべて)
  • 主要指標: 5場スコープ・ken現行構成の全fold合計回収率。 合格基準 = base比 +5.0pt以上 かつ 5fold中4fold以上でbase超え(1発依存の排除)
  • 副次指標(AUC・1位的中・バケット別)は参考表示のみ。これで採否は決めない

追加した特徴量とリーク対策

  • kr_rating: 選手Elo(K=3.0、6艇の着順を15対戦として時系列順に逐次更新)。 各行に入るのはそのレースの更新前の値。kr_rel = kr_rating − レース内平均 (ケンさんのモーター理論と同じ「レース内相対」の形)
  • rising_gap: 直近90日の実測2連対率 − 番組表の全国2連率。 当日を厳密に除外(date < 当日)、窓内12走未満はNaN(LightGBMの欠損分岐に委ねる)
  • 被覆率: kr 100.0%(学習対象=結果確定行) / rising_gap 93.6%
  • いずれも過去結果のみから構成され walk-forward で安全。ただし DBが2025-07-15開始のためElo のバーンインは fold1 時点で約4.5か月と浅い

なぜ効かなかったのか(2つは別々の理由)

  • KR指数: 情報は本物だが、換金されない。 gain寄与11.8%はモデルが実際に強く使った証拠で、 AUCも+0.0041改善した。Eloは「A選手はB選手に勝ち、BはCに勝つ」という 選手をまたぐ推移的比較で、1行ごとの成績列からは木でも作れない新情報だからだ。 それでも回収率が動かないのは、この情報が向上させる「1着の見極め」は すでに市場も鋭い領域だから(ken-motor-theory「市場の1着予想は鋭く、雑なのは 勝てないが絡む艇の値付けだけ」と整合)。的中率≠回収率の再確認
  • 伸びギャップ: そもそもモデルにとって新情報ではない。 gain寄与0.3%。 rising_gapは「直近実績 − 番組表2連率」という引き算だが、モデルは form_last10_top2_rate と national_2rate を既に別々の列として持っており、 木は必要ならその差を自力で表現できる。単因子検証で見えた 「+10pt超の艇は単勝回収77-78%」の正体は予測精度ではなく市場の値付けの遅れ(古いアンカー)で、 出口はモデルではなくオッズ側にある。モデルはオッズを見ないので、 ここに注入しても構造的に換金できない

結論と次にやること

  • v2本体の特徴量には KR指数・伸びギャップとも入れない(検証⑫の選手×場特徴量に続く不合格)。 これで「単因子の発見をモデルに注入する」出口は一巡した
  • KR指数は表示用の資産としては生きている(ラベル税+12.4ptの実測・トップ10の顔認証OK)。 サイトの「軸信頼度」表示等に使う案は回収率とは独立に検討可
  • 伸びギャップの出口はオッズ系の紙上測定(v1凍結方針どおり購入判断には使わない)。 モデル注入では換金できないことが今回確定した
  • 実装上の注意(将来採用する場合): kr_rating は results 由来のため当日レースには値が付かない。 本番投入には「選手ごとの最新レートを保持するテーブル」を db.py に追加する実装が別途必要 (今回の検証結果には影響しない)
